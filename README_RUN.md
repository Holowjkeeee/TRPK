# MATFLOW / KursTRPK - Django + DRF + Vue, итерация 4

Четвёртая итерация проекта курсовой ТРПК. Основа третьей итерации сохранена: итоговый протокол, древовидные сетки и этапное отображение. Backend - Django + Django REST Framework, frontend - Vue 3.

## Что добавлено в четвёртой итерации

- долговременный реестр спортсменов: один `Athlete` используется в разных соревнованиях;
- история принадлежности спортсмена к командам через `TeamMembership`;
- повторный импорт заявки переиспользует существующего спортсмена вместо создания дубля;
- миграция существующих участников в связи спортсмен-команда;
- расширенный демонстрационный набор из 15 весовых категорий;
- массовое добавление набора весов на экране категорий;
- обновлённые Word-шаблон и пример заявки;
- правдоподобная автогенерация результатов: оба цвета победителей, разные способы победы и разные счета;
- обычные дефисы вместо длинных тире в пользовательских текстах.

Подробности находятся в `ITERATION_4_CHANGELOG.md`.

## Что добавлено в третьей итерации

- готовый модуль итогового протокола соревнования;
- предпросмотр итогов из уже сохранённых данных соревнования;
- автоматическая проверка готовности протокола: незавершённые поединки блокируют окончательный выпуск;
- сохранение снимка данных итогового протокола в БД;
- экспорт итогового протокола в DOCX;
- печатная версия страницы протокола (`Печать / PDF` через браузер);
- командный медальный зачёт;
- итоговые места по категориям;
- полная таблица круговой категории и журнал завершённых поединков в DOCX;
- отдельный экран `06 Протокол`;
- готовое тестовое соревнование `[ТЕСТ] Завершённое для итогового протокола`;
- круговая система отображается по отдельным раскрывающимся кругам;
- Nordic отображается по группам A/B, турам и отдельному финальному этапу;
- прямое выбывание отображается древовидной сеткой с линиями перехода;
- квалификация и утешительные ветки вынесены из основной сетки в отдельные блоки;
- команда повторного формирования сетки называется `Сформировать заново`;
- лишние поясняющие тексты на рабочих экранах сокращены;
- при выходе из учётной записи выполняется переход с полной перезагрузкой страницы.

Сохраняется логика второй итерации: 2-5 участников - круговая система, 6-7 - Nordic, 8+ - прямое выбывание с квалификационными и утешительными встречами.

## Итоговый протокол

Backend API:

```text
GET  /api/competitions/<id>/protocol/
POST /api/competitions/<id>/protocol/
GET  /api/competitions/<id>/protocol-download/
```

`GET` возвращает предпросмотр и список блокирующих причин. `POST` создаёт окончательный протокол только если все обязательные поединки завершены и итоговые места определены.

Файл сохраняется в:

```text
backend/media/protocols/YYYY/MM/DD/
```

В БД хранится `FinalProtocol` со снимком данных, пользователем и временем формирования.

## Отображение сеток

### Круговая

Поединки сгруппированы по секциям `1 круг`, `2 круг` и т.д. По умолчанию раскрыт текущий незавершённый круг.

### Nordic

Отдельно показываются:

- группа A;
- группа B;
- туры внутри каждой группы;
- полуфиналы;
- финал;
- встреча за 3 место.

### Прямое выбывание

Основная сетка строится как дерево: карточки поединков расположены по раундам и соединены линиями перехода победителей. Квалификация, утешительные ветки и бронзовые встречи отображаются отдельно.

## Важное по третьей итерации

В проект не добавлена отдельная четвёртая система `double elimination`: по требованиям курсовой остаются круговая, Nordic и прямое выбывание с утешительными ветками. Древовидный интерфейс рассчитан на текущую систему прямого выбывания и её дополнительные ветки.

## Распределение по коврам - Iteration 4.1

Ковёр закрепляется за возрастно-весовой категорией целиком. Одна категория не распределяется между несколькими коврами. При двух коврах младшая возрастная группа назначается на ковёр 1, более старшая - на ковёр 2. Все поединки категории наследуют номер её ковра.


## Изменения интерфейса iteration 4.2

На странице `Сетки и результаты` категория выбирается из выпадающего списка с группировкой по возрасту и сортировкой по весу. Кнопка фиксации поединка называется `Внести результат`. В древовидной сетке увеличены интервалы между карточками, чтобы действия не перекрывали соседние матчи. В верхней панели доступно переключение светлой и тёмной темы; выбор сохраняется в браузере.
